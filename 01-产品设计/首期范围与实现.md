# 首期范围与实现

> [!info] 方案状态
> 以下为设计建议，尚不代表已开发或经用户验证。

| 层级 | 建议范围 | 可验证的完成标准 |
| --- | --- | --- |
| P0 核心流程 | 创建项目、任务、成员加入、提交、确认或退回、记录导出 | 两个真实账号完成一次分工到验收；刷新后数据仍在；权限有效 |
| P0 产品特色 | 原文要求关联；AI拆解草稿与人工确认 | 草稿不会自动覆盖已确认任务；来源可查看；失败可手填 |
| P1 试用后增加 | 轻量文件历史、阻塞提示、待办摘要、分工图片 | 能追溯当前交付版本，导出不把计划混作成果 |
| 暂缓 | 自动贡献评分、文档合并、复杂排程、全量PPT生成、教师后台、双端开发 | 核心价值和使用意愿验证后再决定是否值得投入 |

建议先做手机可用的网页，以团队最熟悉的技术为准。Teamup提出的Vue路线可作为候选；本次没有测试其Supabase与Vercel组合在校园网络下的访问和上传效果，不应直接视为已确定部署方案。应先用校园网和手机网络完成登录、读写、上传的最小验证，再确定后端与托管服务。

前端看板通常不是最难部分；真正需要验证的是多人身份、权限、文件保存、重复提交和状态一致性。AI密钥应留在服务端。文件应限定类型和大小，链接访问应受权限约束。必要的隐私说明和项目删除能力应与试用同时具备。

题目允许模拟数据和人工后台，可先用人工整理AI结果验证流程，但界面和答卷必须标清。若只用本机数据模拟两个成员，不能声称已经支持真实多人协作。商业试用时尤其需要明确交付范围与数据保存期限。

建议按“先闭环、再AI、后视觉导出”组织实现。如果时间不足，首先保住真实提交与确认流程，AI可暂由人工辅助；不为展示复杂度而增加未经验证的能力。

成本判断应记录每组产生的模型调用、存储与流量、人工支持耗时。当前无真实用量，不能承诺低成本盈利。若多数时间消耗在人工建组或整理任务，应将收入认定为包含服务的收入。
